# واجهات السوشيال ليسننج — كيف تعمل (OMA)

هذا المستند يشرح سطوح الاستماع الاجتماعي في OMA مقابل منطق Planable، مع مصدر البيانات الفعلي في الإنتاج.

## مصدر البيانات المشترك

| الطبقة                               | المسؤولية                                                                               |
| ------------------------------------ | --------------------------------------------------------------------------------------- |
| **قواعد الاستماع** (`ListeningRule`) | كلمات مفتاحية، هاشتاغات، منصات، نوع القاعدة (`BRAND` / `COMPETITOR` / `TOPIC`).         |
| **الإشارات** (`ListeningHit`)        | منشورات/تعليقات ملتقطة مع مشاعر، تفاعل، `capturedAt`.                                   |
| **عامل الاستماع** (worker)           | يجري `listening.poll` كل ~5 دقائق للقواعد الحية؛ يقيّم **التنبيهات** يومياً ليوم الأمس. |
| **واجهة API**                        | `/api/v1/listening/*` مع صلاحيات `content.read` / `content.update`.                     |

المنصات: `META_FB`, `META_IG`, `TIKTOK`, `LINKEDIN`, `X`, `REDDIT`, `WEB`, `YOUTUBE`, `WHATSAPP`. فيسبوك وإنستغرام من الحساب المربوط. Reddit بحث عام. يوتيوب وبحث الويب عند مفاتيح الخادم. X وتيك توك ولينكدإن وواتساب من صندوق الوارد فقط. كل قاعدة تحتفظ بإشاراتها عبر المفتاح `(tenantId, ruleId, platform, externalPostId)`.

## 1. Brand (العلامة)

**المسار:** `/app/listening/brand`

**ما تفعله:** تعرض KPIs (إشارات، تفاعل، مشاعر)، مخطط الحجم، وقائمة الإشارات لقاعدة نوع `BRAND`.

**المنطق:** أيقونة «إعداد المراقبة» تفتح لوحة لإدارة عدة قواعد `BRAND` (الاسم، الكلمات، الهاشتاغات، المصادر، إيقاف/استئناف). النتائج والإحصاءات للقاعدة المختارة فقط. `POST /listening/sync` يضع الحالة `QUEUED` ولا يدّعي انتهاء الفحص.

---

## 2. Topic (الموضوع / الهاشتاغ)

**المسار:** `/app/listening/topic`

**ما تفعله:** نفس لوحة Brand لكن لقاعدة `kind === TOPIC` (أو اسم يحتوي topic/hashtag).

**المنطق:** أيقونة الإضافة تنشئ قاعدة `TOPIC`. المواضيع المحفوظة قابلة للاختيار والتعديل والإيقاف، ونتائج كل موضوع معزولة.

---

## 3. Competitors (المنافسون)

**المسار:** `/app/listening/competitors`

**ما تفعله (Planable-style):**

- صف **حجم الإشارات** لكل علامة أنت + منافسين (من قواعد `BRAND` + `COMPETITOR`).
- **Where you stand:** مصفوفة رباعية (حجم × توازن المشاعر).
- **Share of voice:** دائرة نسبية + جدول الحصة وتغيّر النقاط.
- **Sentiment:** أشرطة إيجابي/محايد/سلبي + رصيد النقاط.
- **Share by source:** توزيع الإشارات حسب المنصة وحصتك على كل منصة.

**المنطق:** `GET /api/v1/listening/competitors?from&to&platforms&brandId` يجمع كل الـ hits لكل قاعدة في الفترة، يقارن بالفترة السابقة، ويحسب SOV والمصفوفة من البيانات الحقيقية — وليس بيانات وهمية في الواجهة.

---

## 4. Alerts (التنبيهات)

**المسار:** `/app/listening/alerts`

**ما تفعله:**

- جدول: الاسم، المنصات، شرط التفعيل، آخر تفعيل، مفتاح نشط، حذف.
- نافذة **إنشاء تنبيه**: نوع المشغّل (ذروة حجم، مشاعر إيجابية/سلبية)، عتبة، قنوات إشعار (داخل التطبيق / بريد / Slack — الأخيران مخزّنان للمرحلة القادمة).

**المنطق:**

- CRUD عبر `/api/v1/listening/alerts`، بما في ذلك **تعديل** التنبيه من القائمة (الاسم، المنصات، العتبة، قنوات الإشعار).
- **التقييم اليومي** (worker `evaluate-alerts.ts`): لكل تنبيه نشط، يُحسب أمس UTC على إشارات قاعدة العلامة (`BRAND`). عند التفعيل: `lastFiredAt` + **إشعار داخل التطبيق** + **بريد** (عبر محوّل البريد) + **Slack** (webhook في `WorkspaceSetting.listeningSlackWebhookUrl` أو `LISTENING_SLACK_WEBHOOK_URL`).
- أنواع المشغّل: `VOLUME_SPIKE` (`mentionsPerDay` أو >120% من متوسط 7 أيام)، `SENTIMENT_POSITIVE` / `SENTIMENT_NEGATIVE` (`sharePct`).

## 5. تحليلات معاينة المحتوى (بطاقة Analytics)

**المسار:** معاينة المنشور في المحتوى → أيقونة التحليلات.

**ما تفعله:** تعرض KPIs وتفاصيل عضوية/تشغيل حسب القناة.

**المنطق:** `GET /api/v1/content/:id/channel-analytics` — إن وُجدت `insightsJson` على هدف النشر تُعرض `source: platform`، وإلا مقاييس OMA المحلية (تعليقات، تفاعلات، موافقات) مع رسالة توضيحية. تظهر حالات التحميل والخطأ في اللوحة الجانبية.

## بيانات تجريبية

```bash
SEED_INBOX_DEMO=1 pnpm db:seed:inbox-demo
```

تُنشئ قواعد متعددة (علامة، 3 منافسين، موضوع)، إشارات موزّعة، و3 تنبيهات نموذجية.

## إعداد Slack للتنبيهات

`PATCH /api/v1/workspace/settings` مع `listening_slack_webhook_url` (رابط `hooks.slack.com/services/...` فقط).

## إدارة القواعد

`GET /api/v1/listening/sources` يعيد جاهزية المصادر بلا أسرار: `configured` أو `not_configured` أو `needs_account` أو `public` أو `inbox_only`، مع مسار داخلي لتبويب الحسابات في إعدادات العلامة. القراءة `content.read` والتعديل `content.update`. الإيقاف يبقي الإشارات التاريخية.

## فجوات متبقية

- TikTok / LinkedIn / X / WhatsApp ليست بحثًا عامًا؛ تصل عبر صندوق الوارد للحساب المربوط.
- Web/YouTube يتطلبان `YOUTUBE_API_KEY` و`GOOGLE_CSE_API_KEY` و`GOOGLE_CSE_CX` على الخادم. الواجهة لا تجمع هذه المفاتيح.
- بحث Reddit ويوتيوب والويب يستخدم حتى خمسة مصطلحات لكل قاعدة في كل دورة.
